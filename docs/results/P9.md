# P9 — SEM (PTv3 symmetry classifier): port and legacy checkpoint (2026-10-28, in progress)

Scratch scripts and results: `outputs/p9_sem_gate/` (`sem_gate.py`, `sem_trainframe.py`, `sem_cadframe.py`; not tracked).
Legacy run: `checkpoints/symmetry_ptv3/S2Csym_emb128_bce_vox1cm_wd1e-03_b64_lr1e-04_bbcls-ptv3-v1m1-0-shapenet_v2_mini_ptv3cls_softmax_symbinary_cad_bce_adam_cosineannealing`
(trained 2025-02-25 from scratch, `pretrain: False`; 10k steps).

**Gate (port): passed.** **Finding:** the legacy `embeddings.npy` was exported with inputs the checkpoint was not trained
on, and predicts every CAD as not symmetric. Fix approved by the user (2026-10-28): regenerated embeddings (`cad_bbox`).
Still open: SEM retraining, the E11 reproduction on legacy's exact sample set, timing.

## Port

- `caoa/models/ptv3/`: the legacy `PointTransformerV3/model.py` and `serialization/` (the standalone PTv3 release, not
  full Pointcept), vendored verbatim apart from two imports: `torch_scatter.segment_csr` → `torch.segment_reduce`
  (no wheel for torch 2.9; tested against a loop, values and gradients) and timm's `DropPath` (copied). New
  dependency: `addict`. flash-attn off (`enable_flash=False`): the non-flash path pads the same patches; only the
  attention precision differs.
- `caoa/models/sem.py`: legacy `PT3ClassifierSoftmax` (mean-pooled 128-d embedding → MLP → softmax; outputs
  probabilities in train and eval) with the run's backbone config (`model_config.yaml` = `cls-ptv3-v1m1-0-shapenet_v2_mini`).
- The legacy checkpoint loads strictly (180 tensors). Fed as legacy `build_dataset_sym.py` fed it, it reproduces
  `embeddings.npy`: cosine median 0.9997 / min 0.992 on the 609 test CADs (no augmentation in that export), median
  0.9988 / min 0.932 on the 2,440 train CADs (exported through the train loader, with its random per-axis scale), and
  the same argmax for all 3,049. Differences come from the random surface sampling. Test: `tests/test_sem.py`.

## The legacy embeddings are degenerate

| SEM input | Accuracy | Macro-F1 | Predicted symmetric |
|---|---|---|---|
| Training log (TensorBoard, final; the paper's 95.8 / 94.1) | 95.80 | 94.05 | |
| CAD in its GT box frame, `grid = coord // 1 cm` (the training pipeline), 1,864 val pose pairs | 94.80 | 90.58 | 320 (297 true) |
| CAD in its own bounding-box frame, same pipeline (no annotation), 1,864 val pose pairs | 94.10 | 89.44 | 329 |
| Raw ShapeNet coordinates, `grid = (coord − min) // 1 cm` (the `embeddings.npy` export), 609 test CADs | 72.91 | | **0 of 3,049** |

- The checkpoint was trained on `S2CCompletionSymmetry` (`custom_datasets_pose.py:6662`, `data_source: cad`): each
  pose pair's CAD, 5,000 uniform points, placed by the CAD trs and mapped into the GT box frame (centred, axis-aligned,
  longest side 1), sampled to 8,192, `grid_coord = coord // 0.01` (its `config.json`).
- Two days later (2025-02-27 16:38) `train_config.yaml` was rewritten for the newer `S2CSymmetry`
  (`datasets/custom_datasets_symmetry.py`: raw ShapeNet coordinates, min-subtracted grid, per-CAD split
  `s2c_cad_splits.pkl`) and `embeddings.npy` was exported through it a minute later. On those inputs the classifier
  collapses: 72.9% is exactly the non-symmetric share.
- So the paper's SEM numbers are real (training log), but the only stored embeddings, the ones a "CAPCM+SEM" OCAM
  would load (`symmetry_model_name` in the legacy pose configs), carry no symmetry information. No legacy pose run used
  them (P10a).
- The residual gap to 95.8 is most likely the sample set (legacy's own RelPose dataset; not yet reproduced).
- **E11 / F1 settled:** legacy `eval_sym` = argmax accuracy over a shuffled batch-64 loader with `drop_last` (e.g. 552/576
  = 95.83%); the paper's F1 is the training log's **macro-F1** (94.05).

## Fix: `cad_bbox` embeddings (user decision 2026-10-28, option 2 of 3)

`scripts/build_sem_embeddings.py`: every Scan2CAD CAD (3,049, from `s2c_cad_splits.pkl`) fed as the checkpoint was
trained (5,000 uniform points tiled to 8,192, `grid = coord // 1 cm`) but normalised by the CAD's own bounding box
(centred, longest side 1), so no annotation is used. Output in the legacy format at
`caoa_cache/sem_embeddings_v1/<run>__cad_bbox/embeddings.npy` (1.9 MB). Symmetry accuracy per unique CAD: 86.9% (train) /
87.4% (test); per pose pair (frequency-weighted): 94.1%. Config switch: `sym_embedding: {name, frame: legacy_export | cad_bbox}`.

The rejected options: the legacy file as-is (faithful but carries no symmetry), and the GT box frame (exactly the
training input, but per instance and using the annotation's anisotropic scale, a GT leak into OCAM's scale input).

## E11: the logged sample set (2026-11-03)

The logged accuracies are all multiples of 1/2,048 (32 batches of 64, `drop_last`; `eval_sym` runs over the whole test
loader every 500 steps), so the run was not evaluated on the 1,864-pair RelPose set. Its config sets no class filter, and
the **V2 class rule** gives 2,067 val pairs → 2,048 evaluated, the only one of our rules that fits (RelPose: 1,856; all
matched: 2,432). On that set (scratch `outputs/p9_sem_gate/sem_{trainframe,cadframe}_v2.py`; drop_last means over 200
shuffles):

| SEM input | V2 set (2,067): accuracy / macro-F1 | RelPose set (1,864) |
|---|---|---|
| Training log (final, step 10k) | **95.80 / 94.05** | |
| CAD in its own bbox frame (`cad_bbox`, the fix in use) | **95.26 / 93.36** | 94.10 / 89.44 |
| CAD in the GT box frame (our reconstruction of the training input) | 94.19 / 91.87 | 94.80 / 90.58 |

The regenerated embeddings land 0.5 points from the log on its own sample set. Open: our reconstruction of the training
input scores lower on this set than `cad_bbox`, so it may not match legacy's exactly.
