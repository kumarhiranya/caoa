# P10 — OCAM paper model: SEM, Siamese, Chamfer loss, schedule (in progress, 2026-11-03)

Ablation, one step at a time (user, 2026-10-28): legacy schedule while adding SEM (P10a) → Siamese (P10b) → the paper's
loss (P10c), then the paper's schedule (P10d). Every run: concat completions (`odg_concat_snaug_s2cc_upTransb_comp`),
completion-only, emb 1024, class rule `relpose_cache` (6,663 train / 1,864 val pairs), seed 777, legacy schedule
(batch 64, AdamW 1e-4 / wd 1e-3, cosine to lr/100 over 25k steps, no shuffle). Leak-free (`completion.frame: world`)
unless marked. DGX job 133605 (dgx02), one A100 per run.

## Results

Legacy metric = `s2c_total` (best during training) and `model_final`'s legacy `scannet_class` micro; rotation accuracy
from the same report. S2C criteria = the official Scan2CAD per-object criteria (20 cm / 20° / 20 %) on the 1,864 evaluated
S2C-C objects (`s2c_criteria/*`, see P8.md), instance / class mean.

- **SEM** (`cad_bbox` embeddings, P9): +1.1 legacy final, +0.8 / +2.0 S2C criteria (−center inst / class). With the leaky
  completion frame the numbers rise to 88.4, but that run still reads the GT rotation (P8).
- **Siamese, separate trunks:** about level with SEM alone on the legacy metric (83.8 vs 84.2 final), better on the S2C
  criteria (+2.0 / +1.7 −center, +5.3 plain) and in rotation (93.0 vs 91.5). Twice the inference time (two trunks).
- **Siamese, shared trunk (the paper's design):** 4 points below the separate trunks and below the baseline. Single seed
  each; how much is seed noise is unknown. Chosen for P10c: separate trunks (user agreed to carry the winner forward).
- Training time: ~3 h (P10a), ~5.2 h (P10b) for 25k steps.

## Implementation

- `OCAMObjectOnly(ext_emb_size=128)`: legacy `mnkpv3_emb`, SEM embedding concatenated to the pooled feature.
- `OCAMSiamese(shared=…)` (`caoa/models/ocam.py`): object and CAD trunks (`OCAMEncoder`, one module when shared), legacy
  RelPose heads on 4 × emb + SEM. CAD input: 8,192 uniform points per CAD in its own bounding-box frame (centred, longest
  side 1, no annotation, not augmented), cache `cad_points_v1/cad_bbox_8192.npz` (287 MiB, `scripts/build_cad_points.py`).
- Chamfer loss (`caoa/models/pose_losses.py`, user option 1): CD between the CAD's unit-box points placed by the predicted
  box and by the GT box (2,048 points); all three pose components get gradients through it.
- Parameters: 24 M (object-only), 35 M (shared), 56 M (separate). Tests in `tests/test_pose_pipeline.py`.
