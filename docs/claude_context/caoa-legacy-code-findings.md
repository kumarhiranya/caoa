Findings from the 2026-09-26 audit (part of [[caoa-replication-project]]):

- In the local repo, the raw data are broken symlinks to `/home/mmlab/...` and there's no `checkpoints/` dir. The data, checkpoints and SN-Indoor generator were found on the external drive (see [[caoa-data-locations]]). ODGNet checkpoints and logs are present locally under `ODGNet/experiments/`.
- No SphericalMask code or predictions exist anywhere found, only SoftGroup predictions (`data/objects/softgroup_preds`, 96G).
- Server `pose_mnk` final val totals (GT instances, legacy metric): no completion 71.8%, inst+completion 81.3%, completion-only 87.8% (emb1024; emb512 85.0, emb256 81.3). None of these runs uses SEM.
- ~~ODGNet loaders truncated~~ WRONG (corrected 2026-10-20): both are complete. Their last line has no trailing newline (and CRLF endings), so `wc -l` and sed line ranges miss it. **Read legacy files to their real end** (`awk 'END{print NR}'`, `tail -c`). The real bugs: S2C line 466 unpacks 10 from 9 keys; the context branch in `__getitem__` is unfinished.
- Table 2 provenance: PCN/SN-55/SN-34/S2C-C rows match `[TEST]` logs exactly. The "SN-Indoor+S2C-C+Ctxt_100" row (22.471/2.30) equals the best-VALIDATION score stored in `UpTrans_comp/S2CCompletion/s2ccompletion_upTransb1_comp/ckpt-best.pth`, which was trained on S2C-C only (context r=1m, in_channels=4, Nov 2024). ODGNet validate() class-averages, while test() mixes per-sample and per-class averages. The same Concat checkpoint scores val 33.5/4.3 but test 45.4/23.7.
- Pose eval (`utils/eval_utils.py` calc_pose_accuracy_s2c_nocls) applies a 0.2 translation threshold in normalized units (the object's max extent is 1), because the de-normalization is commented out. The pose target is the Scan2CAD OBB (calc_Mbbox), not the CAD TRS. The GT CAD model is used for the symmetry embedding. SG eval scores matched predictions only, so misses are not penalized.
- The latest `train_pose.py` model is object-only (MinkowskiFCNNP_v3 / _v3_emb with concatenated symmetry embedding), not the Siamese CAD+object model of paper Fig. 4. A Siamese model exists as MinkowskiFCNNRelPose_v1.
- The chamfer loss in code compares the object's own points under GT vs predicted pose, while paper Eq. 5 compares the CAD with the object. Configs use loss weights t2/q1/s2 or t3/q1/s3, while the paper says t2/r3/s2.

Found 2026-10-19 while porting the data layer and the metric:
- S2C-C train/test = the official ScanNet v2 train/val split (lists in `~/research/Github/SoftGroup/dataset/scannetv2/`). `scannet_instance_id` indexes the non-wall/floor `segGroups` in aggregation order, as in SoftGroup's `prepare_data_inst.py`, including its `scene0217_00` duplicate fix.
- Legacy rotation metric (`eval_utils.calc_rotation_diff`): it feeds w-first quaternions to scipy, which expects x,y,z,w, and scores max|xyz Euler| of the relative rotation instead of the geodesic angle. Scale error is mean(|s_pred/s_gt − 1|), but official Scan2CAD uses |mean(s_pred/s_gt) − 1|.
- With `filter_classes: False` (used by every pose_mnk run), `sem_name in VALID_CLASSES_IDX2NAME.keys()` compares a str to int keys, so every sample gets category −1.
- The pose dataset keeps all instance points (`SamplePointsFrom2Array` with downsample off; small objects are tiled without truncation). Training: canonical OBB frame + random yaw in [−180, 180], uniform scale in [0.4, 1.4], translation in [−0.5, 0.5]. Test: world frame scaled to max extent 1, centered at mean − 0.1.
- On the 605 local scenes, 4,358 matched → 3,811 kept (547 have an unannotated instance and a CAD outside the 8 classes); train 3,080 / val 731. Only 3,091 of those are in the 8 eval classes. Neither ratio extrapolates to the paper's 8,535 (6,671 / 1,864), so the paper's filter is unknown. 15 pairs have <50% of their points inside the box (bad annotations); `scene0310_00` model 3 has a zero-thickness box.
- **GT-pose leak in the GT-instance completion path** (found 2026-10-20). `S2CCompletionPoseV2.load_s2c_data_pose_v2` puts instance points into the GT box frame (`custom_datasets_pose.py:5000`, inv of the GT box tMat: GT rotation + GT max-extent scale), runs completion there (`:5024`, `:5063`), then maps back to world for test. So every legacy "with completion" GT-instance number (81.3%, 87.8%, the paper's GT row 86.54%) used GT pose at test time. The SoftGroup path (`SGPredsS2CCompletionPoseVal`, ~`:6436`) completes in a world-oriented frame (scaled by 1/(max bound + 0.5) if the bound > 0.8, mean-centered), so no leak there, but it scores only predictions overlap-matched to GT CADs.
- Local ODGNet checkpoints (`ODGNet/experiments/UpTrans_comp/{S2CCompletion,SNAug,Concat_SN_S2CC,S2CFinetuneSNAug}`, `UpTrans/ShapeNet55_models`, ...). PCN / ShapeNet34 / ShapeNet55 experiment dirs (with `test_S2CC_benchmark`) are in the server copy under `ODGNet/experiments/UpTransS2CC/`. Legacy SEM embeddings: `data/s2c_symmetry/S2Csym_emb128_.../embeddings.npy`. SoftGroup preds: `data/objects/softgroup_preds/{sg_raw?,sg_processed,...}` (96 GB, local).
- **The legacy GT-instance test set (1,864) was built by `S2CCompletionRelPose`'s class rule. CONFIRMED 2026-10-20:** with all 312 val scenes, the rule gives exactly 1,864 with every per-class support equal to inst.csv (test `test_relpose_cache_rule_reproduces_the_legacy_test_set`). Originally found the same day. It writes the SAME cache file as `S2CCompletionPoseV2` (`custom_datasets_pose.py:4831` vs `:5555`), and the cache is reused when present. RelPose relabels `otherfurniture` instances to the CAD's eval class (or drops them); V2 keeps them. Evidence:
  - server `results/{inst,comp,compinst}.csv` have support 1,864 (= the paper's test count) and no `otherfurniture`;
  - `pt3_comp.csv` (2,048, with otherfurniture 238) − 238 + 54 relabelled = 1,864;
  - local val under the RelPose rule (659) fits within every legacy per-class support.
  RelPose also crops context from the full scene including the instance, subsampled.
- **Legacy eval outputs** (server `results/`):
  - per-class CSVs with translation/rotation/scale/total/support plus macro_avg/micro_avg rows (`eval_pose_s2c_v2` with `per_class_results`). `inst.csv` 70.98% micro / 55.93% macro; `comp.csv` 85.68 / 71.68. These date from Feb 21 2025, before the `pose_mnk` runs.
  - SG: `sg_mnk_comp.csv` grouped by CAD taxonomy name, 1,606 samples, 66.75 / 26.26. `sg_mnk_inst.csv` is a byte copy of `comp.csv`.
  - `perclass_results.csv` from the older `calc_pose_accuracy_s2c` (8 VALID_CLASSES).
  - `ODG_*_S2CC.csv`: per-taxonomy F-Score / CDL1 / CDL2.
  Plus `eval_sym` (argmax accuracy) and `tools/eval/evaluate_alignment_scan2cad.py`, a CIS2VR-era protocol (nearest-GT-centre matching, OBB targets, misses counted).
- **Table 1 grouping hypothesis** (2026-10-20; the user said the mapping may be a global var, but none exists in the legacy code or the server git HEAD). Class name = `shapenet2scannet_name(names)` (the ScanNet20 name if one exists), else `sorted(names)[0]`. Deterministic; gives "ash bin", "file", "forte-piano"; bathtub stays "bathtub". Table 1 candidates (2026-10-20): A = Scan2CAD top-8 (other = bed + misc; display/trash bin dropped); B = VALID_SYNSETS (bed column, which Table 1 lacks; desk→03179701 is never used); C = SHAPENET_SYNSET_NAME folded to the 6 shared columns + other (= A plus display/trash bin inside other). - **Legacy SoftGroup dataset caches exist locally:** `data/objects/softgroup_preds/sg_raw/sg_preds_inst_pose_completion_{odg_s2ccompletion_upTransb1,s2c_completion_r32_b64}_spatial0cm_v2c_{train,val}.npy` (Sep/Oct 2024, 0.5–2.6 GB). They hold the exact legacy SG sample sets for P11; the class_dist JSONs are empty.
- **Legacy training loop** (`train_pose9dof`, found 2026-10-20): checks run on `i` before `i += 1`. There is no break inside the epoch, so it trains to the end of the epoch in which i reaches max_steps, and CosineAnnealingLR keeps stepping past T_max (LR rises). Validation also runs at i = 15,000, but `m_train_log.json` is only written at stat steps (every 150), so the last logged validation is 14,000. Reproduced in caoa `scripts/train_pose.py`.
- **Table 1 GT row vs the 1,864 set** (2026-10-20): grouping-C supports are bath 72, bookshelf 113, cabinet 159, chair 965, other 117, sofa 94, table 344. NONE of the paper's GT-row values (nor avg 86.54) is attainable as k/n, so that row came from another sample set or was edited. Recorded in PLAN.md; the user said not to chase it.
- **ODGNet loader recovery** (2026-10-20). ODGNet isn't in the server git and the server copies are identical to the truncated local ones. But `ODGNet/datasets/__pycache__/*.cpython-38.pyc` hold the Feb 28 2025 `S2CCompletionDataset` and Mar 1 2025 `SNAugDataset` (what the Python 3.8 ODGNet env last ran). A decompyle3 venv (py3.8) is in the scratchpad; its output mis-nests 5 functions per file. Repair method: recompile until the bytecode is identical. `models/UpTrans.py` is bytecode-identical to its 3.8 pyc; metrics/runner/builder sources match their 3.8 pycs.
- **Recovered completion loader semantics:** train inputs in the GT CAD frame (inv calc_Mcad) + random yaw; test inputs world-oriented; GT = `resample_mesh(density=2000)`; 4,096 pts; only the 8 VALID_CLASSES after the ('unannotated','otherfurniture') relabel; context = layout points only (inst < 0). The Concat run validated/tested on TRAIN data (`others.subset` doesn't reach the inner `phase`). ODGNet recipe from configs: AdamW 5e-4, wd 5e-4, LambdaLR(20, 0.8, 0.01), bs 32, **400 epochs**.
- **Context flag values disagree:** pose-time context inference uses +1/−1 (`custom_datasets_pose.py:4669`, matches the paper), while the completion loader's (commented / Mar 5) context branch uses 1/0.
- **ODGNet loader review** (2026-10-20, PLAN.md P5a). In the current S2CCompletionDataset.py: line 466 unpacks 10 from 9 keys (crash); `__getitem__` lacks a return (the runner expects a 6-tuple incl. sem_emb, as SNAug returns); the context branch is unfinished. User decisions: context fix mirrors pose-time inference; SNAug's `random.choices` resample is kept. The user approved fix 1 (unpack 9) and fix 3 (sem_emb from semantic_embeddings.npy); fix 2 (return) was withdrawn because the return exists on line 666. `semantic_embeddings.npy` is at legacy `data/ShapeNetSemantic/classification_ptv3/` (only UpTransv2 uses it).
